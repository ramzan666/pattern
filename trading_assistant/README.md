# Crypto Trend Retest · первая версия

Основной код: [trend_retest.pine](trend_retest.pine).
Для вставки в редактор: [trend_retest.txt](trend_retest.txt).

## Запуск в TradingView

1. Откройте обычные свечи BTC/USDT или ETH/USDT на **1H**. Выберите
   конкретную биржу и рынок: сигналы используют именно этот инструмент.
2. В Pine Editor выделите всё и вставьте полный код. В файле одна
   декларация `strategy()`, версия Pine — 6.
3. Добавьте скрипт на график. Он одновременно рисует сценарии и работает
   в тестере стратегий TradingView.
4. Оставьте формат уведомлений **TradingView** для первого запуска.
5. Создайте alert по этому скрипту с условием **только вызовы `alert()`**
   (в интерфейсе может называться «Any alert() function call»).
   Включите нужные push/email-уведомления. Не выбирайте одновременно
   уведомления об исполнении ордеров: код уже формирует события модели.
6. После изменения кода, параметров или инструмента пересоздайте alert:
   TradingView сохраняет снимок скрипта и настроек на момент создания.
   Старый alert удалите: для одной стратегии на одном инструменте должен
   работать один поток уведомлений. ID сценария включает торговые параметры,
   поэтому изменение настроек не переиспользует ID предыдущего плана.

На графике: пунктирный уровень пробоя; синяя цена активации; красная область
SL; зелёная область TP. Подпись различает ожидание, активацию, отмену и
завершение. Панель справа показывает текущий тренд 4H и этап сценария.
Последние 20 сценариев сохраняются, число настраивается. EMA 4H можно
включить в настройках отображения.

## Точные правила

| Этап | LONG | SHORT |
|---|---|---|
| Тренд 4H | EMA50 > EMA200; EMA50 растёт; close > EMA50 | EMA50 < EMA200; EMA50 падает; close < EMA50 |
| Пробой 1H | Закрытие выше максимума предыдущих 20 свечей | Закрытие ниже минимума предыдущих 20 свечей |
| Ретест | low <= уровень пробоя и close > уровень | high >= уровень пробоя и close < уровень |
| Активация | Пробой high свечи ретеста + 1 тик | Пробой low свечи ретеста − 1 тик |
| SL | low ретеста − 0,25 ATR14, округление вниз | high ретеста + 0,25 ATR14, округление вверх |
| TP | Вход + 2 расстояния до SL, округление вверх | Вход − 2 расстояния до SL, округление вниз |

Тренд использует только **закрытые 4H-свечи**, с прогревом по крайней мере
200 исходных свечей. На 1H пробойная свеча не входит в предыдущий диапазон.
Уровень пробоя фиксируется при подтверждении и не двигается.

Ретест разрешён на следующих **1–5 часовых свечах включительно**.
Пробойная свеча не может быть ретестом. У подтверждающей свечи не требуется
отдельный цвет тела: нужны касание уровня и закрытие с правильной стороны.

Вход начинает действовать **со следующей свечи после ретеста**.
Параметры входа, SL, TP и количества фиксируются и не пересчитываются
по новым максимумам, ATR или балансу. На подготовку одного пробоя создаётся
не больше одного плана. Одновременно допускается одна позиция/один сценарий.

Для первой версии принят отдельный срок активации — **2 следующие свечи**,
настраивается. На закрытии последней свечи сначала проверяется зарегистрированное
исполнение/завершение модели, затем отменяется непопавший ордер. Это новое
уточнение реализации, а не результат оптимизации или доказанное улучшение.

Ожидающий сценарий отменяется при истечении своего срока или изменении
закрытого тренда 4H. Если ещё не исполненный вход пережил часовую свечу
с нарушением SL, он отменяется на **закрытии этой 1H-свечи**. Внутри неё
эмулятор может сначала исполнить вход: порядок тогда определяет его модель.
Активная позиция закрывается своим SL/TP, смена EMA сама её не закрывает.
Новый пробой не создаётся на той же свече, где завершён предыдущий сценарий.

## Препятствия и размер позиции

Фильтр препятствий включён по умолчанию: до планового TP не должно быть
уже известного неснятого противоположного свинга 4H. Свинг 3+3 становится
известен после трёх правых 4H-свечей. Задним числом он не участвует в решении.
После касания будущими 1H-свечами уровень удаляется из пула. Настройка
отключается отдельно; отсутствие известного уровня не меняет плановый TP 2R.

Риск по настройке — 0,5% капитала модели **до издержек**. Количество для
линейного USD/USDT-инструмента:

```text
quantity = equity × risk_percent / 100 / (abs(entry − SL) × pointvalue)
```

Количество округляется вниз по `syminfo.mincontract`. Стоимость ограничена
100% капитала (настраивается только вниз), с резервом 1% на издержки.
Поэтому фактический плановый риск может быть меньше 0,5%; именно он показывается
на графике и отправляется в сообщении. Слишком малый размер пропускается.
Исходный капитал модели — 10 000 USD, меняется в свойствах стратегии.
Обратные, quanto-контракты и другой способ пересчёта валют в этой версии
не реализованы.

## Что означает сигнал и результат тестера

Скрипт создаёт стоп-вход и связанный SL/TP в **эмуляторе TradingView**.
К бирже он не подключается. Сообщение об активации отражает зарегистрированный
вход модели; оно не подтверждает исполнение ордера пользователя.
Поле «Вход» — плановая цена. При гэпе модель может исполниться по другой цене.

В live скрипт пересчитывается на обновлениях цены. Уведомление о модели
может прийти при следующем вычислении после исполнения. В истории TradingView
располагает другой детализацией; вход/выход внутри одной свечи зависят от
эмулятора. Bar Magnifier включён, если для него доступны тариф и младшие данные.
Случай входа и выхода внутри одной свечи обрабатывается через `closedtrades`,
чтобы не объявлять такой план отменённым из-за отсутствия открытой позиции.

В свойствах установлены комиссия **0,05% на сторону** и проскальзывание
**2 тика**. Это тики, а не 0,02%. Плановые 2R не включают комиссию и гэпы;
итоговый результат тестера учитывает заданные свойства исполнения.
Проверенного рыночного винрейта или обещания прибыли нет.

## Telegram и ассистент

Порядок подключения описан в [bridge/README.md](bridge/README.md).
Нужны бот от BotFather, chat ID и постоянный сервер с публичным HTTPS.
Токен Telegram хранится только в окружении сервера, в Pine его нет.

1. Запустите мост с секретом, токеном и chat ID по инструкции.
2. В скрипте выберите **Webhook / Telegram** и отдельный случайный webhook-секрет,
   совпадающий с `WEBHOOK_SECRET` сервера. Минимум 24 символа.
3. Пересоздайте alert и задайте HTTPS URL вида `https://ваш-домен/webhook`.
   TradingView сформирует JSON самим вызовом `alert()`; вручную собирать тело
   сообщения не требуется. Для webhook нужна двухфакторная аутентификация
   TradingView и подходящие возможности вашего тарифа.
4. Создайте отдельный alert для каждого инструмента, например BTC и ETH.

События:

| Событие | Назначение | Telegram по умолчанию |
|---|---|---|
| context | Первый live-снимок и закрытый часовой снимок состояния | Тихо сохраняется |
| breakout | Подтверждён пробой, ждём ретест | Тихо сохраняется |
| setup | Ретест подтверждён; известны вход, SL, TP и срок | Сообщение |
| trigger | Вход зарегистрирован в модели | Сообщение |
| cancel | Сценарий отменён с причиной | Сообщение |
| exit | Модель завершила сделку | Сообщение |

Команды ассистента `/btc`, `/eth`, `/status` показывают последние полученные
состояния. Цены берутся из Pine, отдельного генератора сигналов и языковой
модели нет. Снимок может быть устаревшим; бот показывает свежесть и срок,
а не делает вид, что постоянно видит рынок. Проверка статуса не заменяет
приход событий из активного alert TradingView.

Мост принимает webhook быстро, сохраняет события и очередь в SQLite,
убирает повторные входящие события и подавляет старые сигналы входа.
Telegram отправляется отдельным потоком. При сбое сети исходящее сообщение
может повториться: Telegram не предоставляет ключ идемпотентности отправки.

## Проверки

Для Python-моста не нужны сторонние библиотеки:

```bash
python -m unittest trading_assistant.bridge.test_bridge trading_assistant.bridge.test_commands -v
```

Pine дополнительно проверяется сторонним синтаксическим парсером и
ограниченным исполнением AST на искусственных свечах. Эти проверки
покрывают правила и payload, но не заменяют официальный компилятор Pine,
эмулятор исполнения или рыночный бэктест. См. [tests/README.md](tests/README.md).

Перед реальными уведомлениями проверьте скрипт в Pine Editor и тестере
TradingView на выбранной бирже; для первой оценки используйте BTC и ETH
на одинаковом периоде истории с заданными издержками.

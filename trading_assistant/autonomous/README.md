# Самостоятельный бот Bybit → Telegram

Бот сам получает публичные свечи Bybit, рассчитывает сигналы и ведёт виртуальные сделки. Для запуска не нужны TradingView, домен, входящий HTTPS-сервер или торговые ключи Bybit. Нужен компьютер или сервер с Python 3.10+ и доступом к HTTPS Bybit и Telegram.

Настроенный вариант — **Bybit Spot, BTCUSDT и ETHUSDT, только LONG**. Бот не размещает ордера на бирже. Сообщение об активации входа означает виртуальную сделку в модели бота.

## Правила и режимы

| Режим | Сигнальная свеча | Фильтр тренда | Команда |
| --- | --- | --- | --- |
| Основной, по умолчанию | 1H | 4H | `/tf1h` |
| Для коротких сделок | 15м | 1H | `/tf15` |

На закрытой свече старшего ТФ цена должна быть выше EMA50, EMA50 — выше EMA200, а EMA50 должна расти. Затем бот ищет закрытие сигнальной свечи выше максимумов предыдущих 20 свечей и ретест пробитого уровня в следующих пяти свечах. Ретест касается уровня и закрывается выше него.

После ретеста вход планируется на один тик выше его максимума, SL — ниже его минимума с запасом 0,25 ATR14, TP — на расстоянии 2R. Активация возможна в следующих двух сигнальных свечах. Известный подтверждённый свинг старшего ТФ до TP отменяет план. Потеря тренда, истечение срока и нарушение SL до входа также отменяют сценарий.

Риск по расстоянию до SL — до 0,5% виртуального капитала. Размер ограничен доступным капиталом и округляется по правилам инструмента Bybit. По умолчанию каждая пара имеет собственные 10 000 USDT: это два независимых расчёта, а не общий портфель. Комиссия модели — 0,05% на каждую сторону, проскальзывание входа и стопа — два тика. Проверь свою фактическую комиссию Bybit и задай её через `--commission-percent`.

## Запуск с нуля на своём компьютере

Установи Python 3.10+ и Git. На Linux обычно достаточно системного Python; отдельные библиотеки для работы бота не нужны. Для дат используется часовой пояс Москвы. Если система не содержит базы часовых поясов и выдаёт `ZoneInfoNotFoundError`, установи пакет `tzdata` в своё Python-окружение.

Скачай проект и перейди в его корень:

```bash
git clone --branch feature/crypto-trend-assistant https://github.com/ramzan666/pattern.git
cd pattern
python3 -m trading_assistant.autonomous --help
```

В Windows используй `python` вместо `python3`, если так называется установленный интерпретатор.

1. Открой в Telegram официальный **@BotFather**, отправь `/newbot` и создай бота.
2. Открой личный чат с созданным ботом и отправь `/start`.
3. Из корня проекта запусти настройку:

```bash
python3 -m trading_assistant.autonomous --configure
```

Вставь токен BotFather в скрытый запрос терминала. Настройка читает сообщения бота, определяет ID твоего личного чата и сохраняет два параметра в `~/.config/trading-assistant/bybit.env` с правами только для владельца. Если обнаружено несколько чатов или сообщений нет, потребуется числовой ID нужного личного чата. Повторная настройка не перезаписывает существующий файл. Для нового файла можно указать `--configure --env-file /путь/к/новому.env`.

Токен не присылай в чат и не добавляй в Git. [`.env.example`](.env.example) показывает формат настроек, но содержит только заполнители. Env-файл принимает только `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

Проверь доступ к свечам — эта команда работает в памяти, не отправляет сообщения и не меняет сохранённую базу:

```bash
python3 -m trading_assistant.autonomous --once
```

Запусти постоянную работу:

```bash
python3 -m trading_assistant.autonomous \
  --env-file ~/.config/trading-assistant/bybit.env \
  --market spot --direction long --symbols BTCUSDT ETHUSDT \
  --database bybit_assistant.sqlite3
```

При первом запуске бот прогревает индикаторы на закрытой истории, затем отслеживает будущие сценарии. Старые исторические входы не рассылаются. Для остановки нажми Ctrl+C; для продолжения повтори ту же команду с той же базой.

## Команды Telegram

После `/start` или `/menu` появляются постоянные кнопки **BTC**, **ETH**,
**15м**, **1H**, **Статус** и **Помощь** под полем сообщения.
Кнопки запускают те же действия, что команды ниже; ограничения переключения
ТФ сохраняются. Меню также появляется после ответа на обычную команду.

- `/btc` — последний сценарий BTC, тренд и уровни.
- `/eth` — последний сценарий ETH, тренд и уровни.
- `/status` — состояние всех наблюдаемых пар и свежесть данных.
- `/tf15` — переключить сигналы на 15м, фильтр тренда на 1H.
- `/tf1h` — вернуть сигналы 1H и фильтр тренда 4H.

Переключение запрещено, пока хотя бы у одной пары есть ожидание ретеста, готовый вход или активная виртуальная позиция. Дождись отмены или завершения сделки и повтори команду. Успешное переключение сохраняет виртуальный капитал и статистику, заново прогревает индикаторы и начинает искать будущие сигналы. Режим хранится в SQLite и восстанавливается при перезапуске.

Для первого запуска сразу на 15м укажи отдельную новую базу:

```bash
python3 -m trading_assistant.autonomous \
  --env-file ~/.config/trading-assistant/bybit.env \
  --timeframe 15m --database bybit_assistant_15m.sqlite3
```

Если база уже существует, меняй режим командами Telegram. При обычном перезапуске не указывай `--timeframe`: бот восстановит сохранённый режим. Изменение RR, комиссии, риска или состава инструментов также требует отдельной базы, чтобы не переопределять открытые виртуальные сделки.

Для более высокого планового RR при запуске новой базы можно добавить `--rr 3`; значение по умолчанию — `--rr 2`. Все параметры доступны через `--help`.

## Историческая проверка и модель исполнения

```bash
python3 -m trading_assistant.autonomous --replay
python3 -m trading_assistant.autonomous --replay --timeframe 15m
```

`--replay` загружает до примерно 1000 последних закрытых сигнальных свечей и до 1000 свечей старшего ТФ, рассчитывает результаты в памяти и печатает JSON. Он не использует Telegram и не меняет базу. Это грубая симуляция по OHLC выбранного сигнального ТФ; комиссии и проскальзывание включены. Незавершённая позиция указывается отдельно, её текущая прибыль или убыток не включаются в капитал. Прогрев индикаторов сокращает фактический участок поиска сигналов.

В постоянном режиме активация и выход проверяются на **закрытых минутных свечах**. Уведомление может запаздывать примерно на минуту плюс интервал проверки — по умолчанию 15 секунд, а при проблемах сети дольше. Если порядок достижения SL и TP внутри свечи неизвестен, модель выбирает SL; гэпы учитываются по цене открытия. Вход и выход в одной минутной свече тоже возможны. Эти результаты могут отличаться от модели исполнения TradingView и реальной биржи.

SQLite хранит сценарии, статистику виртуальных сделок и очередь доставки. При перезапуске бот догоняет закрытые свечи; устаревшие сообщения об входах подавляются. Одна база предназначена для одного процесса: второй экземпляр автоматически отклоняется блокировкой. Соседний файл `*-lock` может остаться после остановки; удалять его для перезапуска не требуется. Не запускай одновременно этот бот, старый Telegram-мост и другие программы, читающие обновления **того же Telegram-бота** через `getUpdates`.

Автотесты используют искусственные свечи и ответы API. На этапе разработки доступ к публичному Bybit API из облачной среды был заблокирован HTTP 403, поэтому реальный рыночный бэктест и винрейт не подтверждены. Если `--once` завершается ошибкой доступа, проверь доступность публичного API Bybit из своего окружения; без него бот не сможет получать данные.

Проверка кода из корня проекта, без настоящих сообщений и торговых ордеров:

```bash
python3 -m unittest trading_assistant.autonomous.test_autonomous trading_assistant.bridge.test_bridge trading_assistant.bridge.test_commands -v
```

## Круглосуточная работа на Ubuntu 24.04

Серверу достаточно исходящего HTTPS; домен, Caddy и открытые входящие порты боту не нужны. Используй один экземпляр процесса. Выполни команды на своём сервере:

```bash
sudo apt update
sudo apt install -y python3 git tzdata
sudo useradd --system --user-group --home-dir /var/lib/bybit-assistant --shell /usr/sbin/nologin bybit-assistant
sudo git clone --branch feature/crypto-trend-assistant https://github.com/ramzan666/pattern.git /opt/bybit-assistant
cd /opt/bybit-assistant
```

Если бот ещё не настроен, создай локальный файл с токеном через скрытый запрос:

```bash
python3 -m trading_assistant.autonomous --configure
```

Установи секретный файл и службу:

```bash
sudo install -o root -g root -m 600 "$HOME/.config/trading-assistant/bybit.env" /etc/bybit-assistant.env
sudo install -o root -g root -m 644 trading_assistant/autonomous/bybit-assistant.service.example /etc/systemd/system/bybit-assistant.service
sudo systemctl daemon-reload
sudo systemctl enable --now bybit-assistant.service
sudo systemctl status bybit-assistant.service
```

Служба читает `/etc/bybit-assistant.env`, работает от отдельного пользователя и хранит базу в `/var/lib/bybit-assistant/state.sqlite3`. При обычном перезапуске служба сохраняет выбранный в Telegram ТФ. Смотреть журнал и перезапускать службу можно так:

```bash
sudo journalctl -u bybit-assistant.service -n 50 --no-pager
sudo systemctl restart bybit-assistant.service
sudo systemctl stop bybit-assistant.service
```

Сначала проверь `--once` на сервере, затем настрой службу. Не запускай локальную копию с тем же Telegram-токеном одновременно с сервером. Сделай резервную копию базы и env-файла перед переносом на другой сервер; не публикуй их.

# Проверка Pine Script

Из корня репозитория:

```bash
python -m venv /tmp/pine-check
/tmp/pine-check/bin/python -m pip install -r trading_assistant/tests/requirements-dev.txt
/tmp/pine-check/bin/python -m trading_assistant.tests.check_pine
```

Команда разбирает фактический `trend_retest.pine` сторонним парсером
`pynescript` и исполняет его AST в ограниченном локальном интерпретаторе.
Сохранённые AST и pickle-файлы не используются. При изменении Pine проверка
всегда читает текущий исходник. Неизвестные вызовы и конструкции завершают
проверку ошибкой, а не пропускаются.

Проверяются размер позиции и лимит стоимости, контрактный шаг, запрет
неправильного графика и webhook без секрета, допуск только закрытых 4H данных,
прогрев EMA, LONG/SHORT, закрытие пробоя и ретеста, сроки ретеста и активации,
фиксация уровней, отмены по SL/тренду/препятствию, уведомления и отсутствие
дублей, расширение и остановка зон. Фактически сформированный Pine JSON
проходит production-валидатор моста и SQLite-дедупликацию.

Это **не официальный компилятор Pine и не брокерный эмулятор TradingView**.
`request.security`, ATR, скользящие диапазоны, pivots, EMA и параметры инструмента
подставляются сценариями. `strategy.entry/exit/cancel` только записываются;
`position_size` и `closedtrades` задаются явно, чтобы проверить реакцию Pine
на исполнение и вход/выход внутри одной свечи. Рисование проверяется локальными
объектами, без интерфейса TradingView и механизма отката realtime-переменных.
Сторонний парсер проверяет грамматику, но не все ограничения типов и пространства
имён TradingView. Часть статических проверок фиксирует ключевые настройки
источника, включая диапазон предыдущих свечей и `lookahead_off`.

Проверка не отправляет Telegram-сообщения, не запускает ордера на бирже и
не оценивает прибыльность на рыночных данных. Перед применением нужен запуск
в Pine Editor и Strategy Tester с комиссиями и проверкой на отдельных данных.
